# GridPool V2.2 Coordinated Cutover

Status: implemented in this tree for consensus version `22`; coordinate node
configuration and deployment before activation.

## Ships In Version 22

- CONS-020: deterministic Monotonic Snapshot Reconciliation for fully validated
  sibling boundary reserves, with block-hash family isolation and bounded
  member retention.
- CONS-001: new previous-parent proofs received by direct ingress after the
  local boundary cannot enter the canonical unpaid reserve. Already-known
  pre-boundary lineage remains usable.
- CONS-002: paid-once removal is keyed to the payout snapshot proven by the
  winning block coinbase context, including cross-snapshot payment.
- CONS-005 status: one-block competing-boundary family restoration is covered.
  Two-block replay and paid-confirmation rollback vectors remain follow-up work.

## Does Not Ship

- CONS-003 remains blocked on the human support-fee decision.
- CONS-010 peer-header snapshot activation remains deferred. A peer header may
  provisionally freeze work under existing policy but does not activate a V2.2
  payout snapshot.

## Compatibility And Rollout

Version `21` nodes keep V2.1 local-boundary and merge-forward behavior. Version
`22` nodes perform MSR only for explicit, fully validated family members.
Existing handshake and state-bundle gates reject consensus-version mismatch;
there is no soft merge between versions. The state-bundle schema is version `3`
because V2.2 adds explicit immutable family-member boundary reserves.

Operators should upgrade all participating nodes and sample configuration
together, verify consensus version `22` in status/handshakes, then monitor the
reconciliation counters for family mismatches, no-op pressure, payout changes,
and convergence. Simulation results informed this cutover but are not a
security guarantee.
